# Remaining tooling advisories — October 13, 2026

**Disposition: review completed; risks are not accepted or fully remediated.** The installed application lockfile remains unchanged from `e24abe7`. The audit reports 73 affected package entries (54 high, 19 moderate, zero critical), tracing to five root advisories below. Inherited counts overlap and are not a count of independent exploitable vulnerabilities.

Public npm registry metadata was rechecked at 21:58 UTC. Installed package source, parent ranges, CI, application imports and the final export source maps were inspected. None of these five affected npm packages appeared as modules in the inspected iOS, Android, web or worker maps. **Absence from these maps is not proof of non-exploitability:** build processes, CLI signing, dependency execution, other configurations and hosted build images remain separate trust boundaries. No hosted signing service or production credential was inspected.

## Why audit-fix suggestions are not accepted fixes

- `npm audit` proposes **Expo 44.0.6** for Forge/uuid and **NativeWind 2.0.11** for the parser. These are downgrades across the current SDK 57 / NativeWind 4 stack, not compatible security patches.
- It proposes **Jest 30.5.2** for some braces/sprintf chains. Installed `jest-expo 57.0.5` and latest `57.0.6` still declare Jest 29 internals. Changing the top-level Jest alone neither proves preset compatibility nor removes the independent Tailwind braces chain.
- Latest **Tailwind 4.3.3** is not compatible with installed/latest **NativeWind 4.2.7**'s Metro implementation: `nativewind/dist/metro/tailwind/index.js` explicitly rejects non-v3 Tailwind. Its broad package peer range is insufficient evidence of runtime compatibility.
- Latest **Expo 57.0.28** is an in-family maintenance candidate, but the public dependency metadata does not establish removal of the unpatched Forge dependency. A routine SDK patch cannot be called an advisory fix without inspecting its resolved lockfile and testing it.

No `npm audit fix --force`, audit ignore, broad major override, signing-key change or risk waiver was applied.

## Isolated compatibility evidence

Candidate-only installation: `../tooling/advisory-candidates`, lifecycle scripts disabled, packages pinned to parser **7.1.6** and uuid **11.1.1**. The project package files and installed tree were unchanged. Separate Node 24.21.0 child processes had a 96 MiB JavaScript heap and 3-second probe / 30-second compilation deadlines. This is bounded local testing, not a hostile-code sandbox.

- Parser substitution occurred only in each child process. The existing Tailwind CLI, NativeWind preset, `global.css` and repository content sources produced identical baseline/candidate bytes: web **42,135 bytes**, SHA-256 `304dd84776884c310b3548af8c8b1e381dce015d12498dc71e7f0e431d628d2c`; iOS-mode CSS **34,872 bytes**, SHA-256 `19446b4ca7e4212ded3f92fe656c0ff19645a8616aebf4b9ec449abc06eb0bcb`. This does not cover every selector, native CSS-to-style transformation or device layout.
- Candidate UUID passed 1,000 calls through xcode's existing `generateUuid()`: unique 24-character uppercase hexadecimal values. No real project, certificate or device was mutated.
- The installed sprintf-js failed on a synthetic excessive precision specifier with the expected `RangeError`; the child caught it. The bounded braces nested-alternation probe was accepted on this Node build and did **not** reproduce a stack overflow. A larger literal-only input was rejected by the existing 10,000-character limit. Neither result refutes the published recursive-walker advisory.
- Existing CI has read-only GitHub token permissions and a 15-minute job deadline; it also executes dependency installation and PR-controlled code. These observations do not prove that every remote build environment isolates secrets or that an input-parsing failure is harmless.

Sanitized raw evidence and the reproducible local probe are adjacent to this checkout: `advisory-registry-review.json`, `advisory-compatibility-results.json`, and `tooling/advisory-candidates/compatibility.cjs`. They contain no production data or signing material. The 195-unit/24-component/all-platform evidence from `e24abe7` remains the application baseline; these candidate tests do not modify or replace it.

## Decision boundary

No remaining root is being marked fixed in the installed lockfile. Parser/uuid have concrete patched candidates with limited compatibility evidence; braces/Forge/sprintf have no published patched release verified today. The release gate needs supported fixes or explicit, bounded owner risk decisions based on the real build/signing environment. A statement that packages are absent from app source maps cannot supply that decision.
